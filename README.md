# Dossier RAG Assistant

A retrieval-augmented chatbot over case-dossier records, built to explore **access-controlled RAG**: each office login can only retrieve its own office's records, and the system refuses to answer when it has no relevant context instead of letting the LLM guess.

> **All data is synthetic.** `data/dossiers.json` is generated by `dosier_records.py` with fake names and cases. No real records are used or included.

## How it works

```
question
  → greeting? → canned reply (no search, no LLM)
  → follow-up rewrite (Gemini turns "their names" into a standalone question)
  → scope check (question names another office? → refuse)
  → access filter (office login → only that office's records)
  → metadata filters (nationality, entry type extracted from the question)
  → relevance gate (close vector match OR distinctive keyword match, else "I don't know")
  → hybrid retrieval (vector search + BM25, merged with reciprocal rank fusion)
  → cross-encoder reranker (top 30 → top 5)
  → grounded prompt → Gemini → answer + cited dossier numbers
```

Design decisions:

- **Security lives in retrieval, not the prompt.** The office filter is applied to the vector query, the BM25 index (one index per office) and the exact-ID lookup, so forbidden records never reach the model.
- **No context, no LLM call.** If retrieval returns nothing, the app answers "I don't know" without calling the model, which removes a whole class of hallucinations.
- **Exact dossier numbers** (`DOS/000123/2026`) use a direct, access-checked lookup, since embeddings match IDs poorly.

## Evaluation

`make_questions.py` generates 21 questions with ground truth computed from the data. `evaluate_all.py` scores each retrieval mode.

| Retrieval mode | attribute | exact_id | status | unanswerable |
|---|---|---|---|---|
| vector only | 0.44 | 1.00 | 0.67 | 1.00 |
| + metadata filters | 1.00 | 1.00 | 0.67 | 1.00 |
| + BM25 hybrid | 1.00 | 1.00 | 0.60 | 1.00 |
| + reranker | 1.00 | 1.00 | 0.93 | 1.00 |

Scores are precision@5 (questions with more than 5 true matches) or hit@5 (5 or fewer), averaged per question type. "unanswerable" is the share of nonsense questions where nothing was retrieved.

Caveats: the set is small (5–6 questions per type), so differences of a few points are noise. `exact_id` is 1.00 because of the direct lookup above, not because of search. This measures retrieval only, not answer quality.

## Limitations

- RAG cannot count or list "all" records. It sees the top 5, so "how many…" or "show all…" questions need a database query.
- Only the last few chat turns are used to resolve follow-ups.
- The login picker in the app is a **demo**. In a real system the backend must derive the office from the authenticated session, never from the browser.
- Typos and run-together words ("frommumbai") defeat keyword matching.

## Run it

```bash
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env        # then put your Google AI key in .env
```

```bash
python dosier_records.py      # optional: regenerate the synthetic data
python make_questions.py      # optional: regenerate the evaluation questions
python evaluate_all.py        # print the evaluation table
streamlit run dossier_chatbot.py
```

The vector database (`chroma_db/`) is built automatically on first start. Embedding 10,000 records on CPU takes a few minutes.

Optional API: `uvicorn api:app --reload`, then open `http://localhost:8000/docs`.

## Files

| File | Purpose |
|---|---|
| `pipeline.py` | Ingestion, access control, filters, hybrid search, reranking, prompt |
| `dossier_chatbot.py` | Streamlit chat UI using Gemini |
| `api.py` | FastAPI `/ask` endpoint |
| `dosier_records.py` | Synthetic data generator |
| `make_questions.py` | Evaluation question generator |
| `evaluate_all.py` | Scores every retrieval mode |

## Stack

Python, ChromaDB, sentence-transformers (embeddings and cross-encoder reranker), rank_bm25, LangChain + Google Gemini, Streamlit, FastAPI.
